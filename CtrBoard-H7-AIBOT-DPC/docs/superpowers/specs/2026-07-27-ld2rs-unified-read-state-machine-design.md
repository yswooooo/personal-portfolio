# LD2-RS 统一读事务状态机设计

## 目标

把状态/速度读取和编码器位置读取统一到同一组顶层读状态中，通过独立的读子事务枚举区分读取内容。修复编码器事务启动失败可能卡住状态机的问题，同时保持原有速度控制、写事务、安全停机和 VOFA 输出行为。

## 状态结构

顶层电机状态恢复为通用读写阶段：

`IDLE → READ_REQ → WAIT_READ → READ_DONE → WRITE_REQ → WAIT_WRITE → WRITE_DONE → IDLE`

电机 FSM 增加读子事务字段，取值为：

- `STATUS_SPEED`：连续读取 PrB.05/PrB.06。
- `ENCODER_POSITION`：连续读取 PrB.24 的高低两个寄存器。

顶层 `READ_REQ` 根据读子事务组装请求；`WAIT_READ` 根据读子事务校验、解析响应并决定下一状态。C 语言枚举不嵌套，因此顶层阶段和读子事务使用两个枚举类型、两个状态字段表达。

## 正常数据流

1. 新周期将读子事务设为 `STATUS_SPEED`，清零读重试计数。
2. 状态/速度读取成功后：
   - 更新状态、反馈转速、RTT 和在线状态。
   - 将读子事务切换为 `ENCODER_POSITION`。
   - 清零读重试计数并重新进入 `READ_REQ`。
3. 编码器读取成功后：
   - 将两个 16 位寄存器拼接为有符号 32 位位置。
   - 更新对应的 `g_vofa_speed` 观察字段。
   - 进入 `READ_DONE`，随后执行原有目标速度写入。

## 重试和失败处理

状态/速度与编码器子事务分别拥有最多 `APP_LD2RS_TASK_MAX_RETRY`（3）次 APP 逻辑事务尝试。每次逻辑事务继续沿用 BSP 内部最多 3 次物理尝试，因此单个读子事务最坏可产生 9 次物理发送。

- CRC、站号、功能码、长度或字节数校验失败：计入当前子事务的 APP 重试。
- BSP `TIMEOUT/ERROR`：释放总线并计入当前子事务的 APP 重试。
- `bsp_rs485_start_tx()` 返回 `ERR_BUSY`：不计重试，保留 `READ_REQ`，下一轮再尝试。
- `bsp_rs485_start_tx()` 返回其他错误：计入当前子事务的 APP 重试，避免永久停留在请求态。
- 状态/速度重试耗尽：保持原有策略，设置强制零速并进入速度写入。
- 编码器重试耗尽：保留上一次有效编码器值，本轮不再读取，进入 `READ_DONE` 并继续速度写入；下一控制周期重新尝试读取编码器。
- 编码器失败不更新离线统计，不触发强制零速。

## 安全控制

急停、遥控器掉线或 SWA 向下时：

- 编码器请求尚未发出：跳过编码器子事务，进入 `READ_DONE`。
- 编码器事务已经在等待：取消当前观测事务、释放总线并进入 `READ_DONE`，使零速写入优先执行。

状态/速度读取及写事务原有安全策略不变。取消能力由 BSP 提供明确接口，避免在 APP 层直接操作 UART 或把仍在工作的总线强行标记为空闲。

## 调度规则

成功完成一个 Modbus 事务后继续沿用现有轮询调度策略。编码器启动失败、校验失败、超时、错误或安全取消时，在完成必要的总线释放和重试判断后：

- 尚有重试：允许调度器切换电机，之后重试同一读子事务。
- 编码器重试耗尽或被安全取消：保留当前电机调度权，使其尽快进入速度写入。
- 状态/速度重试耗尽：沿用原状态机进入强制零速写入。

## 读子事务分类与扩展约定

所有根据 `read_transaction` 分类的代码必须写成完整的显式分支：

```c
if (read_transaction == STATUS_SPEED) {
    /* 状态/速度子事务 */
} else if (read_transaction == ENCODER_POSITION) {
    /* 编码器位置子事务 */
} else {
    /* 未知子事务安全兜底 */
}
```

不得使用裸 `else` 隐式代表某一个合法子事务。未知值不得组装或发送 Modbus 请求，也不得按状态/速度或编码器格式解析响应；必须设置 `force_zero_speed = 1u` 并进入 `WRITE_REQ`。

未来增加新的读寄存器请求时，必须同步修改并检查以下位置：

1. 在 `motor_read_transaction_t` 中增加新的子事务枚举值。
2. 在统一 `READ_REQ` 的显式 `else if` 链中增加对应寄存器地址和请求数量。
3. 在统一 `WAIT_READ` 的显式 `else if` 链中增加对应响应长度校验、解析和成功后的下一状态。
4. 在读失败处理函数的显式 `else if` 链中定义该子事务重试耗尽后的策略。
5. 明确该子事务是否参与安全跳过、离线统计和强制零速策略。
6. 增加行为测试，覆盖成功、失败重试耗尽及未知枚举不会误访问寄存器。

## 验证

- 源码级状态机回归测试覆盖：
  - 两种读子事务共用 `READ_REQ/WAIT_READ`。
  - 状态/速度成功后切换到编码器子事务。
  - 两种读子事务分别执行 3 次 APP 重试。
  - 编码器启动错误不会卡在 `READ_REQ`。
  - 编码器重试耗尽保留旧值并继续写速度。
  - 编码器等待期间触发安全停机时取消事务并进入写零速路径。
  - 未知读子事务不发起 Modbus 请求，强制零速并进入 `WRITE_REQ`。
