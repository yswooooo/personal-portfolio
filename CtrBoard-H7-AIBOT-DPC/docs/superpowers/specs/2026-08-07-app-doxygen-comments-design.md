# App Doxygen 注释完善设计

## 目标

为 `App/Inc`、`App/Src` 和 `Middleware/Filter` 中的函数、枚举及结构体补充统一、简洁的 Doxygen 注释，使读者无需进入函数体即可理解接口用途、参数方向、返回语义、数据单位、关键调用约束和典型使用方法。

## 覆盖范围

- `App/Inc/*.h` 中的公开函数声明、枚举、结构体及其成员。
- `App/Src/*.c` 中的 `static` 内部函数定义。
- `Middleware/Filter` 中的公开滤波接口及其实现。
- 已存在但信息不完整或与实现不一致的 Doxygen 注释。
- 与函数和数据类型直接相关、能够解释物理意义或状态机语义的全局实例说明。

`app_config.h` 的配置宏已经具有逐项说明，不在本次批量重写范围内；仅在发现明显缺失或错误时修正。

## 注释位置

- 公开 API 的主要说明写在头文件声明之前，作为调用者可见的唯一权威说明。
- `.c` 文件中的公开函数实现不机械复制头文件全文；已有实现级注释保留并纠正明显错误。
- `static` 内部函数在其定义之前添加完整 Doxygen 注释，因为这些函数不会出现在公开头文件中。
- 枚举值和结构体成员使用行尾 `/**< ... */`，让字段含义与定义保持相邻。

## 注释格式

函数注释统一包含适用的以下字段：

```c
/**
  * @brief      一句话说明函数用途
  * @param[in]  input   输入参数含义和单位
  * @param[out] output  输出参数含义和单位
  * @return     返回值的具体语义
  * @note       调用时机、NULL 行为或状态机约束
  */
```

具体规则如下：

- 使用中文描述，保留寄存器名、状态名、单位和代码标识符的英文形式。
- 指针参数明确标注 `[in]`、`[out]` 或 `[in,out]`。
- 非 `void` 函数说明每类返回值的含义；布尔返回值明确 `true` 和 `false` 分别代表什么。
- 速度、角度、时间、编码器计数等字段必须标明 `rpm`、`rad`、`m/s`、`ms`、`us` 或 `count` 等单位。
- 状态机函数说明推进对象、总线前置条件以及可能修改的关键状态。
- 不为显而易见的赋值和局部变量添加逐行注释，避免注释噪声。

## 文件级处理

- `app_ld2rs_task.h/.c`：说明电机事务阶段、读取事务类型、FSM 运行时、调度器、速度反馈结构和所有内部状态机辅助函数。
- `app_encoder_speed.h/.c`：说明有效采样、序列号、时间戳、差分计数、角度增量、速度估算结果以及更新条件。
- `app_chassis_motor_ctrl.h/.c`：补齐结构体成员、公开控制接口和内部寄存器写入函数的参数方向及返回语义，并纠正单位描述。
- `app_led_indicator.h/.c`：说明初始化和周期更新函数的调用时机、优先级和输出状态。
- `Middleware/Filter/Inc/low_pass_filter.h`：说明一阶低通滤波公式、参数范围、首次初始化、周期调用方式和调用者保存历史输出的责任，并提供可直接参考的 `@code` 示例。
- `Middleware/Filter/Src/low_pass_filter.c`：使用 `@copydoc` 关联公开接口说明，避免头文件和实现重复维护两份文档。

## Filter 使用说明要求

`low_pass_filter_update_float()` 是无状态纯函数，模块内部不保存任何历史值。头文件必须明确以下用法：

```c
float filtered = initial_input;
const float alpha = sample_period_s / (sample_period_s + time_constant_s);

filtered = low_pass_filter_update_float(raw_input, filtered, alpha);
```

- 首次使用时可将 `filtered` 初始化为首个输入值，以避免从零开始造成启动跳变。
- 每个固定采样周期调用一次，并将上次返回值作为下次 `last_output`。
- `alpha` 越小，输出越平滑但响应越慢；`alpha` 越大，输出越接近当前输入。
- 当前实现不裁剪 `alpha`，调用者必须保证其位于 `[0, 1]`。
- 每个信号分别保存自己的历史输出，因此同一函数可独立处理多个信号。

## 行为约束

- 不改变函数签名、结构体布局、枚举值、全局变量、宏值或运行逻辑。
- 不移动类型或函数，不重命名现有标识符。
- 不将模块私有实现细节暴露为新的公开 API。
- 保持工程当前换行和编码风格，避免无关的大范围格式变化。
